# 4.1 Môi trường phát triển và triển khai

Mục này mô tả setup phần cứng, hệ điều hành và stack công nghệ mà toàn bộ thực nghiệm trong Chương 4 chạy trên đó — đảm bảo tính **tái lập** (Reproducibility) của các kết quả.

## 4.1.1 Phần cứng

Toàn bộ phát triển và thực nghiệm chạy trên một laptop dev của sinh viên — cấu hình điển hình của một sinh viên CNTT năm cuối:

**Bảng 4.0: Cấu hình phần cứng máy dev**

| Thành phần | Cấu hình |
|---|---|
| Model | Acer Aspire A715-42G |
| CPU | AMD Ryzen 5 5500U (6 cores / 12 threads, 2.1–4.0 GHz) |
| RAM | 22 GiB DDR4 |
| GPU dedicated | NVIDIA GeForce GTX 1650 Mobile (4 GB VRAM) |
| GPU integrated | AMD Radeon (Lucienne) |
| Storage | NVMe SSD |

**Ghi chú về GPU**: GTX 1650 chỉ có 4 GB VRAM, không đủ cho fine-tune mBERT (cần ≥ 8 GB cho batch ≥ 8). Vì vậy quá trình fine-tune NER được thực hiện trên **Google Colab Free Tier (Tesla T4, 16 GB VRAM)** — chi tiết ở [mục 4.3](./4.3_skill_extraction_eval.md). GPU local chỉ dùng để inference (load model đã train, encode SBERT). Mọi component khác (Multi-criteria Freshness engine, crawler, Market Intel aggregation) chạy thuần CPU — không yêu cầu GPU.

## 4.1.3 Stack công nghệ

### Database

| Database | Phiên bản | Vai trò |
|---|---|---|
| **PostgreSQL 15** | docker image `postgres:15` | Lưu trữ structured: `jd_raw` (1.604 JD), `skill_trends`, `skill_user_cv`, `skill_freshness_history`, `skill_freshness_alerts`, `crawler_log` |
| **ChromaDB 0.5.5** | docker image `chromadb/chroma:0.5.5` | Vector store cho semantic search (3 collection: skill, career, chatbot) |

Hai instance PostgreSQL riêng biệt: `postgres_main` (port 5432, cho auth/user) và `skill_postgres` (port 5433, cho skill service + JD + freshness analytics).

### Backend services

5 microservices được chạy độc lập, giao tiếp qua REST API (chi tiết kiến trúc xem [mục 3.6](../chuong3/3.6_thiet_ke_kien_truc.md)):

| Service | Port | Stack | Trách nhiệm |
|---|---|---|---|
| **api_gateway** | 5000 | ASP.NET Core 9 | Entry point, JWT auth, email digest, rate limiting |
| **ner_service** | 5001 | FastAPI 0.109 + uvicorn | NER mBERT + SBERT encode + Cascade Matching |
| **skill_service** | 5002 | FastAPI 0.109 | Multi-criteria Freshness, Market Intel, Ontology, Cascade |
| **crawler_service** | 5003 | FastAPI + APScheduler | JD crawler ITviec + TopCV, cross-source dedup, daily cron |
| **frontend** | 5173 (dev) / 3000 (prod) | React 19.2 + Vite 5.4 + Tailwind 3.4 + Recharts 3.8 | CV Health Dashboard + Market Intel Dashboard |

## 4.1.4 Triển khai và automation

### Docker Compose

File `docker-compose.yml` ở root khai báo toàn bộ stack: 2 PostgreSQL, 3 ChromaDB, và các microservices. Lệnh duy nhất:

```bash
docker compose up -d   # khởi động full stack
docker compose down    # tắt toàn bộ
```

Mọi service có healthcheck đảm bảo startup theo đúng thứ tự (Postgres ready → Skill service start; ChromaDB ready → NER service start).

### Cron daily cho crawler

Crawler **không chạy trong docker** — chạy host-level qua cron để có quyền sleep linh hoạt vượt rate-limit. Crontab entry:

```cron
@reboot       sleep 300 && /home/dungken/.../daily_crawl.sh
0 9 * * *     /home/dungken/.../daily_crawl.sh
```

Script `daily_crawl.sh` kiểm tra stamp file `/tmp/cv_crawler_last_run`: nếu stamp = today → skip (idempotent), nếu khác → chạy ITviec + TopCV crawler `--fetch-details` rồi cập nhật stamp. Pattern này đảm bảo cron hoạt động ổn định cả khi máy được bật/tắt qua đêm (xem chi tiết [mục 3.3.1](../chuong3/3.3_thiet_ke_pipeline_crawl.md)).

### Google Colab cho fine-tune

mBERT fine-tune chạy 1 lần trên Google Colab Free T4 (~25 phút/3 epochs), checkpoint download về local + push vào `services/ner_service/models/ner/final/`. Không cần Colab cho inference — model load vào RAM local mất ~3s, inference ~2–5s/CV trên CPU.

## 4.1.5 Tools phát triển

- **Editor**: VSCode (với Python, Pylance, ESLint, Tailwind IntelliSense extensions).
- **Version control**: git + GitHub (private repo) — mọi commit có message rõ ràng + Co-Authored-By tag cho AI-assisted changes.
- **API testing**: HTTPie + Bruno (giai đoạn dev), pytest fixtures (CI).
- **Database inspect**: DBeaver Community + `psql` CLI cho query ad-hoc.
- **Browser**: Chrome DevTools cho frontend debug + Network tab kiểm tra payload Market Intel (~180 ms first call, < 1 ms cached).

## 4.1.6 Test framework

- **pytest** cho unit + integration test các service Python (Freshness formula, cross-source dedup, structured extraction).
- **Manual test scripts** dưới `services/skill_service/scripts/` chạy validate được (`validate_multi_freshness.py`, `dump_market_intel_stats.py`) — kết hợp đóng vai trò "live integration test" trên DB thật.
- Frontend test thủ công qua browser — không setup Jest/Playwright trong scope DATN do nhân lực 1 sinh viên.

## 4.1.7 Tóm tắt tái lập

Để tái lập **mọi kết quả thực nghiệm trong Chương 4** trên một máy mới:

1. **Cài** Ubuntu 24.04 + Python 3.12 + Docker + Node 18 + .NET 9.
2. **Clone repo**, `cd cv_assistant`.
3. **Khởi động data layer**: `docker compose up -d postgres_main skill_postgres skill_chromadb`.
4. **Tạo venv + install**: `python3 -m venv .venv && .venv/bin/pip install -r services/skill_service/requirements.txt`.
5. **Migrate DB**: `PYTHONPATH=. .venv/bin/python services/skill_service/scripts/init_db.py`.
6. **Restore JD snapshot** từ dump (~80 MB SQL).
7. **Chạy validate scripts** — sẽ in ra đúng số liệu trong các mục 4.2–4.5:
   - `validate_multi_freshness.py` → Δ = +57.73, Cohen's d = 11.93, monotonic PASS
   - `dump_market_intel_stats.py` → KPIs 1.604 JD, 792 company, 522 skill, 34 insight

Toàn bộ tham số (ngưỡng SBERT 0.65, trọng số $\omega_d$ theo seniority, prompt template parser) được lưu trong file config có version control — đảm bảo cùng input + cùng commit hash sẽ cho cùng output.
