# 2.4 Web Crawling và xử lý JD thực tế

## 2.4.1 Các phương pháp crawl web (HTTP request, Selenium, AJAX endpoint)

Web crawling là quá trình tự động duyệt các trang web, tải nội dung và trích xuất thông tin có cấu trúc. Một crawler điển hình gồm các thành phần: **Fetcher** (gửi HTTP request và nhận response), **Parser** (trích xuất các trường cần thiết từ response), **Scheduler** (quản lý hàng đợi URL và retry khi lỗi), và **Storage** (lưu trữ dữ liệu đã trích xuất). Cho bài toán crawl JD từ các nền tảng tuyển dụng, có ba phương pháp chính, mỗi phương pháp có trade-off khác nhau về tốc độ, độ tin cậy và khả năng vượt qua các cơ chế chống bot.

**Phương pháp 1 — HTTP Request với HTML parsing.** Đây là cách tiếp cận đơn giản nhất: gửi HTTP request trực tiếp đến URL trang đích (sử dụng thư viện như `requests` của Python), nhận về HTML và parse bằng BeautifulSoup hoặc lxml. Ưu điểm: nhanh (mỗi request ~0.3-1 giây), nhẹ (không cần trình duyệt), dễ scale. Hạn chế: chỉ hoạt động với các trang server-side rendered (nội dung có sẵn trong HTML response); không xử lý được JavaScript dynamic loading, và bị các cơ chế anti-bot cơ bản chặn (như kiểm tra User-Agent, Cloudflare JavaScript challenge).

**Phương pháp 2 — Selenium/Browser automation.** Sử dụng các thư viện như Selenium hoặc Playwright để điều khiển một trình duyệt thật (Chrome, Firefox) load trang. Sau khi trang đã render đầy đủ (kể cả JavaScript), lấy `page_source` và parse như Phương pháp 1. Ưu điểm: vượt được các cơ chế chống bot phức tạp hơn, xử lý JavaScript dynamic loading, mô phỏng tương tác người dùng (click, scroll). Hạn chế: chậm (mỗi page ~3-5 giây để render), tốn RAM (~300-500 MB/instance), khó scale, và **không phải lúc nào cũng vượt được Cloudflare Turnstile hiện đại** — các cơ chế detection mới có thể phát hiện `navigator.webdriver` hoặc các signal browser automation khác.

**Phương pháp 3 — AJAX endpoint reverse-engineering.** Đây là cách tiếp cận được đề tài chọn sau khi phát hiện cả hai phương pháp trên đều có hạn chế trên ITviec/TopCV. Quan sát thực tế: các nền tảng tuyển dụng hiện đại có UI dạng SPA (Single Page Application), nội dung được load thông qua các **AJAX endpoint** (REST API trả về JSON hoặc HTML fragment). Ví dụ ITviec dùng endpoint `/it-jobs/<slug>/content?job_index=0&locale=en` để load nội dung JD chi tiết, TopCV dùng `/job-view-detail?id=<job_id>` (yêu cầu header `X-Requested-With: XMLHttpRequest`). Các AJAX endpoint này **thường không có Cloudflare protection mạnh** vì được thiết kế để frontend gọi với tốc độ cao.

**So sánh ba phương pháp**:

| Phương pháp | Tốc độ | RAM | Vượt CF cơ bản | Vượt CF Turnstile | Khả năng scale |
|---|---|---|---|---|---|
| HTTP Request | ~0.3-1s | ~10 MB | ❌ | ❌ | Cao |
| Selenium | ~3-5s | ~300-500 MB | ✅ | ⚠️ (tùy version) | Thấp |
| AJAX endpoint | ~0.3-0.8s | ~10 MB | ✅ | ✅ | Cao |

Đề tài chọn **kết hợp AJAX endpoint (chính) + HTTP request với cloudscraper (hỗ trợ)** — vừa nhanh, vừa nhẹ, vừa vượt được các cơ chế chống bot hiện tại của ITviec và TopCV.

## 2.4.2 Xử lý Cloudflare bot protection (cloudscraper)

Cloudflare là một CDN và security service được sử dụng rộng rãi để bảo vệ website khỏi tấn công DDoS và bot scraping. Cloudflare cung cấp nhiều tầng bảo vệ với độ phức tạp tăng dần:

- **Tầng 1 — JavaScript challenge**: server trả về một trang chứa JavaScript thực hiện tính toán đơn giản (proof-of-work nhẹ), client phải execute và submit kết quả mới được truy cập nội dung thật.
- **Tầng 2 — Turnstile**: thay thế cho reCAPTCHA, yêu cầu user (hoặc bot) giải các challenge phức tạp hơn, kiểm tra browser fingerprint và behavioral signals.
- **Tầng 3 — Bot Fight Mode + ML detection**: phân tích pattern truy cập theo thời gian, IP reputation, device fingerprint.

**cloudscraper** là một thư viện Python kế thừa `requests` nhưng có thêm khả năng **tự động giải Cloudflare JavaScript challenge (Tầng 1)**. Cách hoạt động: khi gặp response chứa challenge, cloudscraper parse JavaScript trong response, mô phỏng execution (dùng JS engine nhúng), tính toán đáp số và gửi lại request kèm cookie kết quả. Toàn bộ quy trình tự động và nhanh (~0.5-1 giây overhead so với plain `requests`).

**Hạn chế của cloudscraper**: chỉ vượt được Tầng 1 và một phần Tầng 2 (các trường hợp Turnstile cũ). Với Turnstile mới (Cloudflare cập nhật 2024-2025), cloudscraper trả về HTTP 403. Trong trường hợp đó, có 3 cách xử lý:

1. **Chuyển sang Selenium + undetected-chromedriver** (wrapper patch các signal bot-detection như `navigator.webdriver`).
2. **Tìm AJAX endpoint không bị CF chặn** (như Phương pháp 3 ở mục 2.4.1).
3. **Chấp nhận giới hạn**, chỉ crawl được phần listing không có chi tiết.

**Áp dụng vào đề tài.** Sau khảo sát thực tế trên ITviec và TopCV (5/2026):

- **ITviec listing pages**: cloudscraper pass dễ dàng (chỉ có Tầng 1). Sleep 0.3-0.8s/request.
- **ITviec detail pages**: cloudscraper pass với endpoint `/content` AJAX, nhưng salary nằm trong full HTML page có Cloudflare Turnstile mạnh hơn → dùng JSON-LD trên full page với sleep 2-4s/request (rate-limited cao).
- **TopCV listing pages**: cloudscraper pass (Tầng 1).
- **TopCV detail pages**: full URL `/viec-lam/<slug>/<id>.html` bị Cloudflare Turnstile chặn cả cloudscraper lẫn Selenium → đề tài **chuyển sang AJAX endpoint `/job-view-detail?id=X`** với header `X-Requested-With: XMLHttpRequest` — vượt qua được hoàn toàn.

**Politeness và rate limiting**. Ngay cả khi vượt qua được bot protection, vẫn cần tôn trọng server. Đề tài implement `PoliteHttpClient` (`services/http_client.py`) với:

- **Sleep ngẫu nhiên (jitter) 0.3-0.8 giây** giữa các request AJAX để mô phỏng người dùng thực.
- **Sleep 2-4 giây** cho các request có rate limit cao (JSON-LD salary fetch).
- **Exponential backoff retry** cho HTTP 429 (Too Many Requests) và 5xx (server error).
- **Rotation User-Agent** giữa Chrome, Firefox, Edge.
- **Tuân thủ robots.txt** — kiểm tra trước khi crawl, không truy cập các đường dẫn bị disallow.

## 2.4.3 Pipeline parse JD: listing + detail enrichment

Pipeline crawl của đề tài chia thành **hai giai đoạn** tách rời để tối ưu tốc độ và độ tin cậy:

**Giai đoạn 1 — Listing crawl (lấy nhanh, ít field)**. Duyệt qua các trang listing của ITviec và TopCV (theo category, theo page). Mỗi trang chứa 20-25 JD cards, từ mỗi card trích xuất các trường có sẵn ngay trong card mà không cần fetch detail:

- `title`: tiêu đề công việc.
- `company`: tên công ty.
- `url`: link tới detail page.
- `location`: vị trí làm việc (Hà Nội, HCM, Đà Nẵng, ...).
- `skills_raw`: danh sách skill tag hiển thị trên card.
- `posted_date`: ngày đăng (relative time, parse về absolute).
- `role_hint`: role inferred từ URL slug (ITviec) hoặc category đang crawl (TopCV).
- **TopCV bổ sung**: `min_exp_listing`, `max_exp_listing` (từ badge "X năm"), `degree_listing` (từ tag overflow), `salary` (từ `label.title-salary`).

Giai đoạn này nhanh, mỗi page ~1-2 giây. Toàn bộ ITviec ~44 pages × 20 JDs/page ≈ 880 JDs crawl trong ~1 phút.

**Giai đoạn 2 — Detail enrichment (lấy chậm hơn, đầy đủ field)**. Với mỗi JD đã có URL từ Giai đoạn 1, fetch trang chi tiết để bổ sung các trường còn thiếu:

- `description`: mô tả công việc đầy đủ (cần để structured extraction và NER).
- `salary_min`, `salary_max`, `salary_currency`: từ JSON-LD JobPosting block (ITviec) hoặc `salary` field listing (TopCV).
- `work_mode`: onsite/hybrid/remote (parse từ description bằng regex).
- `min_exp`, `max_exp`, `seniority`, `degree_required`: derive từ description bằng `StructuredExtractor` (rule-based regex VN/EN).

Sau đó pipeline gọi **Skill Matching cascade** (xem [mục 2.5](./2.5_pipeline_trich_xuat_ky_nang.md)) để chuẩn hóa `skills_raw` thành `skills_canonical`, và áp dụng **cross-source deduplication** qua `job_group_id` (xem [mục 2.3.2](./2.3_market_intelligence.md)) để gắn nhóm các JD cùng vị trí từ nhiều nguồn.

**Adapter pattern cho multi-source.** Mỗi nguồn (ITviec, TopCV) có cấu trúc HTML và endpoint khác nhau. Đề tài dùng **adapter pattern**: định nghĩa interface chung `IJDCrawler` với các method `list_categories()`, `fetch_listing()`, `fetch_full_jd_signal()`, mỗi nguồn implement riêng. Thêm nguồn mới chỉ cần viết 1 file adapter, không phải sửa pipeline.

```python
class IJDCrawler(Protocol):
    def list_categories(self) -> list[str]: ...
    def fetch_listing(self, category: str, page: int) -> list[RawJD]: ...
    def fetch_full_jd_signal(self, url: str) -> Optional[dict]: ...

class ItviecCrawler(IJDCrawler):
    # AJAX endpoint /it-jobs/<slug>/content + JSON-LD salary
    ...

class TopCVCrawler(IJDCrawler):
    # AJAX endpoint /job-view-detail?id=X
    ...
```

**Lịch trình cron và stamp file.** Crawler chạy daily qua cron Linux với cơ chế **stamp file** (`/tmp/cv_crawler_last_run`) để đảm bảo chỉ chạy 1 lần/ngày kể cả khi máy được reboot nhiều lần:

```cron
# Chạy lúc 09:00 sáng nếu máy đang bật
0 9 * * * /path/to/daily_crawl.sh
# Fallback: 5 phút sau reboot nếu chưa crawl hôm nay
@reboot sleep 300 && /path/to/daily_crawl.sh
```

Script `daily_crawl.sh` kiểm tra stamp file: nếu stamp = today → skip; nếu khác → chạy crawl và update stamp. Cách này đảm bảo cron hoạt động ổn định kể cả khi máy được tắt qua đêm và bật lại sáng hôm sau.

**Lưu trữ dual storage.** Sau crawl, dữ liệu được lưu vào hai store song song để phục vụ các use case khác nhau:

- **PostgreSQL** (bảng `jd_raw`): lưu structured fields (title, company, skills_canonical, salary, work_mode, ...) cho Market Intel analytics. Schema có cột `jd_key` (primary key SHA1 URL), `job_group_id` (cross-source dedup), `parse_version` (track phiên bản parse).
- **ChromaDB** (collection `real_jds`): mỗi JD encode bằng Sentence-BERT (`all-MiniLM-L6-v2`) thành vector 384 chiều, lưu kèm metadata. Cho phép truy vấn semantic search các JD gần với CV của user (Opportunity Window).

**Tuân thủ pháp lý và đạo đức**. Web crawling cho mục đích nghiên cứu học thuật là hợp lệ khi tuân thủ:

1. **Robots.txt**: tuân thủ các đường dẫn allow/disallow.
2. **Rate limiting**: sleep ngẫu nhiên giữa các request, không tạo gánh nặng cho server.
3. **Không phân phối lại dữ liệu thô**: dữ liệu chỉ phục vụ phân tích nội bộ và demo trong báo cáo, không công khai.
4. **Không thu thập thông tin cá nhân**: crawler chỉ lấy JD (mô tả công việc, kỹ năng, công ty), không thu thập thông tin cá nhân của ứng viên hay nhân sự.
5. **Trích nguồn rõ ràng**: báo cáo ghi rõ dữ liệu crawl từ ITviec/TopCV trong thời gian nào.
